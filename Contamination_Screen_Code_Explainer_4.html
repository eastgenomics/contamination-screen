Setup Setup functions

parse_args() Lines ~54–120 Setup

Purpose: defines every command-line argument, validates types, sets defaults, and returns a Namespace object. Every configurable setting in the tool lives here.

Takes

  • Nothing (reads sys.argv implicitly)

Returns

  • argparse.Namespace — an object where each argument is an attribute, e.g. args.peak_count

Key points for reviewers:

  • The module docstring is passed as description=__doc__ so --help shows it verbatim.
  • formatter_class=argparse.RawDescriptionHelpFormatter preserves line breaks in the docstring when printing help — without it, argparse would collapse it to one line.
  • type=Path on path arguments means argparse converts the string to a Path object automatically — no manual conversion needed later.
  • type=float and type=int mean invalid input (e.g. passing --peak-count abc) gives a clean error message rather than crashing later with a confusing TypeError.
  • The default for --threads is min(8, os.cpu_count() or 1) — this is computed at parse time, so the default shown in --help is the actual CPU count of the machine, not a hardcoded number.
Note on --min-dp

The default is 99, not 100. This matches the clinical pipeline filter expression FORMAT/DP<99, which removes variants with DP strictly less than 99 — meaning DP=99 is retained. If you changed the default to 100, DP=99 variants would be lost. The docstring explains this carefully.

_run() Lines ~127–131 Setup helper

Purpose: a minimal wrapper around subprocess.run() that logs the command at DEBUG level before running it.

Takes

  • cmd: List[str] — the command to run
  • check: bool = True — whether to raise on non-zero exit

Returns

  • subprocess.CompletedProcess

Why bother? With --verbose, every bcftools command is logged before it runs. This is invaluable for debugging — if a bcftools command fails, you can see exactly what was executed. Without this wrapper, you would have to add logging to every subprocess call individually.

get_sample_name() Lines ~133–148 Setup helper

Purpose: extracts the sample name from a VCF file's header. In a VCF, the 10th column (0-indexed: column 9) of the #CHROM line is the sample name.

Takes

  • vcf: Path — path to a VCF file

Returns

  • str — sample name, or the filename stem if the header cannot be read

Runs bcftools view -h (print header only) and scans each line for the one starting with #CHROM. Splits that line on tabs and returns parts[9]. The fallback to vcf.stem ensures the function never raises — if the VCF is unreadable, the filename is used instead and a warning is logged.

Phase 1 Phase 1 — Pre-filtering functions

_csq_gnomad_fields() Lines ~156–166 Phase 1

Purpose: detects which gnomAD allele frequency fields are present in a VCF's VEP annotation, so filter_vcf() knows which fields to filter on.

Takes

  • src: Path — path to the input VCF

Returns

  • List[str] — e.g. ["gnomADg_AF", "gnomADe_AF"] or ["gnomADe_AF"] or []

Runs bcftools +split-vep --list on the VCF. This prints one line per CSQ subfield in the format index<TAB>field_name. The function extracts field names (column 2) and returns any that match gnomADg_AF or gnomADe_AF.

Why is this needed? Two VEP configurations have been used across different runs. Older VCFs only have gnomADe_AF; newer ones have both gnomADg_AF and gnomADe_AF. The gnomAD filter step in filter_vcf() must only reference fields that actually exist in the VCF — otherwise bcftools would fail. This function makes the pipeline self-adapting.

filter_vcf() Lines ~169–254 Phase 1

Purpose: runs a single VCF through the four-stage bcftools filtering pipeline and writes the filtered, indexed output file.

Takes

  • src: Path — input VCF
  • dst: Path — output VCF path
  • pass_only: bool
  • min_dp: int
  • min_af: float
  • max_gnomad: float

Returns

  • Nothing — writes files to disk
  • Raises RuntimeError if any bcftools stage fails

The four pipeline stages:

  1. Stage 1 — bcftools view -f PASS (optional): removes soft-filtered variants (those with anything other than PASS in the FILTER column). These are variants that Sentieon TNfilter deemed unreliable — strand bias, low quality, etc. Skipped if --include-non-pass is set.
  2. Stage 2 — bcftools filter -e 'FORMAT/DP<N || AF<N': removes low depth and low VAF variants. The -e flag means "exclude variants where this expression is true". Both conditions are combined with || so a variant is removed if either condition is met.
  3. Stage 3 — bcftools +split-vep --columns - -a CSQ -p CSQ_ -s worst: extracts subfields from the VEP CSQ INFO field into individual INFO tags prefixed with CSQ_. The -s worst flag picks one transcript per variant (the worst-consequence transcript), preventing duplicate rows for multi-transcript variants. After this stage, gnomAD AFs are available as CSQ_gnomADg_AF and CSQ_gnomADe_AF. Crucially, these become properly-typed floating-point fields, enabling arithmetic comparison in Stage 4.
  4. Stage 4 — bcftools view -e 'CSQ_gnomADg_AF>=T || CSQ_gnomADe_AF>=T': removes variants with gnomAD AF above the threshold. Only adds this filter expression if gnomAD fields were found by _csq_gnomad_fields(). Output is bgzipped (-Oz) to dst.

After all four stages succeed, bcftools index -t creates a tabix index for the filtered VCF — required for downstream tools.

Return code checking order matters

The code checks all four return codes after calling p4.communicate() — not before. This is intentional: you must let all processes run to completion before inspecting their exit codes. Checking p1's return code while p2–p4 are still running could cause a deadlock if p1's stderr buffer is full.

The filter cache

Before running the pipeline, main() checks whether a .filter.json sidecar file exists alongside the filtered VCF and whether its contents match the current filter settings. If they match, Phase 1 is skipped for that sample. This means re-running with identical settings is nearly instant. If you change any filter argument (e.g. raise --min-dp), the sidecar will not match and all VCFs are re-filtered automatically.

Phase 2 Phase 2 — Loading

load_vcf() Lines ~258–315 Phase 2

Purpose: queries a filtered VCF with bcftools query and constructs a pandas DataFrame of variants. After this function, the code never reads a VCF file directly again.

Takes

  • vcf: Path — filtered VCF (output of Phase 1)

Returns

  • pd.DataFrame — columns: chrom, pos, ref, alt, filter_col, af, gene

The bcftools query format string:

"%CHROM\t%POS\t%REF\t%ALT\t%FILTER\t[%AF]\t%INFO/CSQ_SYMBOL\n"

Each %-prefixed token is replaced by the corresponding VCF field. [%AF] in square brackets extracts the sample-level FORMAT/AF field (the allele fraction measured from the reads). %INFO/CSQ_SYMBOL fetches the gene name that was extracted into an INFO field by +split-vep in Phase 1. The output is tab-separated plain text, one line per variant.

The deduplication step:

df = df.drop_duplicates(subset=["chrom", "pos", "ref", "alt"], keep="first")

Even with -s worst in the split-vep stage, some VCFs can emit multiple rows for the same variant with different gene annotations. Deduplication ensures each variant position appears only once. The keep="first" policy is safe — the AF value is the same regardless of which transcript annotation is kept.

Error handling: if CSQ_SYMBOL is not found (e.g. running on a VCF that has not been through Phase 1 filtering), the function logs a specific hint to re-run with --force-refilter and raises a RuntimeError rather than silently producing wrong results.

Phase 3 Phase 3 — Core algorithm

_find_peaks() Lines ~319–370 Phase 3

Purpose: given an array of log2-ratio values, builds a histogram and identifies two peaks: the tallest bin overall (usually the germline-sharing peak near ratio=1), and the tallest bin in the non-unity region (the contamination signal).

Takes

  • log2_ratios: np.ndarray — array of log2(VAF_B/VAF_A) values
  • bin_width: float — histogram bin width

Returns

  • dict with keys: overall_log2, overall_count, overall_fraction, nonunity_log2, nonunity_count, nonunity_fraction

The overall peak is simply np.argmax(counts) — whichever bin has the most variants. For any run with shared common germline variants, this is almost always near log2=0 (ratio=1). It is reported but not used for flagging.

The non-unity peak is the key. The code masks out the unity zone (bins where |center| <= 0.3) and then finds np.argmax() on the remaining bins only:

nonunity_mask = np.abs(centers) > 0.3
nonunity_counts = counts.copy()
nonunity_counts[~nonunity_mask] = 0   # zero out the unity zone

if nonunity_counts.max() > 0:
    idx = np.argmax(nonunity_counts)    # tallest non-unity bin
    result["nonunity_log2"]   = float(centers[idx])
    result["nonunity_count"]  = int(counts[idx])   # note: uses original counts
    result["nonunity_fraction"] = float(counts[idx]) / n_total
counts[idx] not nonunity_counts[idx]

The count is read from counts[idx] (the original, unmasked array), not nonunity_counts[idx]. This is correct — the mask only affects which bin is chosen as the maximum, not how many variants are in it. Both values would be identical here (the unity zone is set to 0, not negative), but using the original array is clearer intent.

_compare() Lines ~373–465 Phase 3 — core algorithm

Purpose: the central function of the entire tool. Merges two samples' variant DataFrames, computes log2 ratios, calls _find_peaks(), assigns directionality, and returns a results dict plus optionally the merged DataFrame.

Takes

  • name_a, name_b: str — sample names
  • df_a, df_b: pd.DataFrame — variant DataFrames
  • bin_width: float
  • include_shared_df: bool — whether to return the merged DataFrame

Returns

  • Tuple[dict, Optional[pd.DataFrame]] — results dict + merged DataFrame (if requested)

Step 1 — merge on shared variant positions. Only variants present in both samples are kept (inner join on chrom, pos, ref, alt). n_shared is the count of these. If fewer than 2 shared variants are found, the function returns early with default NaN values — there is nothing useful to compute.

Step 2 — remove AF=0 variants. Any variant where either sample has AF=0 would produce a division by zero or infinite log2 ratio. These are filtered out with a warning logged at DEBUG level.

Step 3 — compute ratios and call _find_peaks().

ratios              = merged["af_b"] / merged["af_a"]
merged["log2_ratio"] = np.log2(ratios.values)
peaks = _find_peaks(merged["log2_ratio"].values, bin_width)

Step 4 — assign directionality from the non-unity peak.

plr = peaks["nonunity_log2"]   # the peak log2 ratio

if plr < 0:      # VAF_B < VAF_A → A is source
    result["contamination_source"]    = name_a
    result["contamination_recipient"] = name_b
    result["contamination_fraction"]  = 2.0 ** plr
else:            # VAF_B > VAF_A → B is source
    result["contamination_source"]    = name_b
    result["contamination_recipient"] = name_a
    result["contamination_fraction"]  = 2.0 ** (-plr)

The contamination fraction estimate is 2^plr (for negative plr) or 2^(-plr) (for positive plr) — always a value between 0 and 1 representing the fraction of the recipient's library that came from the source.

Step 5 — mark in-peak variants. Variants in the non-unity peak bin (within half a bin-width of the peak centre) are flagged with in_peak=True in the merged DataFrame. These appear in the detail TSV output and are highlighted in the histogram plots.

The include_shared_df flag: in Phase 3, all pairs are compared with include_shared_df=False — the merged DataFrame is computed but then discarded, saving memory. Only flagged pairs are re-compared in Phase 4 with include_shared_df=True to retrieve the variant-level detail needed for TSVs and plots. See Document 1 for the full explanation of why this two-pass approach is used.

_worker() Lines ~468–472 Phase 3

Purpose: a thin unpacking wrapper around _compare(). ThreadPoolExecutor.map() calls functions with a single argument; this function receives a tuple and unpacks it before calling _compare().

def _worker(args_tuple: tuple) -> dict:
    name_a, name_b, df_cache, bin_width = args_tuple
    result, _ = _compare(name_a, df_cache[name_a], name_b, df_cache[name_b],
                         bin_width, include_shared_df=False)
    return result

The _ variable discards the shared DataFrame — in Phase 3 we only want the results dict. This is a Python convention for "I know there's a second return value but I don't need it".

_apply_flags() Lines ~497–539 Phase 4

Purpose: converts the list of raw result dicts to a DataFrame, computes within-run z-scores, and applies all flagging conditions. The flagged column this adds is the primary clinical output.

Takes

  • results: List[dict]
  • min_shared, peak_count_thresh, n_shared_z_thresh
  • freemix: Optional[dict]
  • freemix_threshold: float

Returns

  • pd.DataFrame — all pairs with added n_shared_z and flagged columns

Z-score computation:

n_mean = df["n_shared"].mean()
n_std  = df["n_shared"].std()
df["n_shared_z"] = (df["n_shared"] - n_mean) / n_std if n_std > 0 else 0.0

The base flag (three conditions, all must be true):

base_flag = (
    (df["n_shared"]   >= min_shared)          # enough variants to assess
  & (df["peak_count"] >= peak_count_thresh)   # clear non-unity peak
  & (df["n_shared_z"] >= n_shared_z_thresh)   # unusually high sharing
)

Note: & not and. In pandas, & is element-wise boolean AND across a Series. Python's and keyword does not work on Series.

FREEMIX gating: when a FREEMIX dict is provided, a pair is only flagged if the recipient's FREEMIX also meets the threshold. fillna(False) ensures pairs with no FREEMIX data are not flagged.

df["recipient_freemix"] = df["contamination_recipient"].map(freemix)
freemix_flag = df["recipient_freemix"] >= freemix_threshold
df["flagged"] = base_flag & freemix_flag.fillna(False)

The .map(freemix) call is a vectorised dictionary lookup — for each recipient name in the column, it looks up the corresponding FREEMIX value from the dict. Names not in the dict become NaN.

Orchestration main()

main() Lines ~718–1009 Entry point

Purpose: the entry point for the entire script. Calls parse_args(), configures logging, then runs the four phases in sequence.

Phase 1 loop — the cache check

For each VCF in the input directory, main() checks whether a valid cached filtered VCF already exists:

# Build what the filter config should look like
current_cfg = {
    "pass_only":  not args.include_non_pass,
    "min_dp":     args.min_dp,
    "min_af":     args.min_af,
    "max_gnomad": args.max_gnomad,
}

def _cfg_matches() -> bool:
    # Read the .filter.json sidecar file and compare
    if not cfg.exists(): return False
    import json as _json
    try:
        return _json.loads(cfg.read_text()) == current_cfg
    except Exception: return False

if not args.force_refilter and dst.exists() and tbi.exists() and _cfg_matches():
    logging.info("  Reusing: %s", dst.name)
else:
    filter_vcf(vcf, dst, ...)

The _cfg_matches() function is defined inside the loop as a closure. It captures cfg and current_cfg from the enclosing scope. This pattern avoids passing these values as parameters and keeps the cache logic self-contained.

Phase 3 — thread pool setup

tasks = [
    (na, nb, df_cache, args.bin_width)
    for na, nb in combinations(sample_names, 2)
]

if args.threads > 1:
    with ThreadPoolExecutor(max_workers=args.threads) as executor:
        raw_results = list(executor.map(_worker, tasks))
else:
    raw_results = [_worker(t) for t in tasks]

When --threads 1 is passed, the thread pool is bypassed entirely and comparisons run in a simple list comprehension. This makes debugging easier — exceptions are raised directly in the main thread with a clean traceback, rather than being wrapped by the executor.

Phase 4 — the second _compare() pass for detail output

shared_cache: Dict[tuple, pd.DataFrame] = {}
for r in output_pairs:
    na, nb = r["sample_a"], r["sample_b"]
    _, shared = _compare(na, df_cache[na], nb, df_cache[nb],
                         args.bin_width, include_shared_df=True)  # ← second call
    shared_cache[(na, nb)] = shared

Only the top --max-output flagged pairs (default 10, sorted by peak_count descending) get this second pass. For a 30-sample run with 5 flagged pairs, this is 5 extra comparisons — negligible. It avoids holding all pairwise DataFrames in RAM for the entire Phase 3 run.

The if __name__ == "__main__" guard

if __name__ == "__main__":
    main()

This is a Python idiom meaning: "run main() only if this file is executed directly, not if it is imported as a module". Without it, main() would be called immediately if you did import contamination_screen from another script — which would be very unexpected. This guard also allows the functions to be imported and tested individually in unit tests without triggering the full pipeline.
