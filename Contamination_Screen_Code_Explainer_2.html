01 Shebang line and module docstring

contamination_screen.py Lines 1–15 
#!/usr/bin/env python3
"""
contamination_screen.py

Pairwise cross-sample contamination detector for tumour sequencing panel VCFs.

Screens a cohort of VCFs for cross-sample contamination by detecting shared
variants at consistent VAF ratios. Uses a dual-peak approach: reports both the
dominant ratio peak (typically ratio ~1 from shared germline) and the dominant
non-unity peak (the contamination signal).

Designed for Uranus pipeline (CUH Bioinformatics) haematological oncology panel
VCFs output by the eggd_vep stage. Input VCFs must already have been normalised
with bcftools norm -m -any.
"""
  • 1
    Shebang line (#!/usr/bin/env python3). This tells your operating system which interpreter to use when running the file directly (e.g. ./contamination_screen.py). /usr/bin/env python3 is portable — it finds whichever python3 is first on your $PATH, rather than hardcoding a path like /usr/bin/python3. You only need this if you plan to execute the file directly; running it as python3 contamination_screen.py ignores this line.
  • 2
    Module docstring. A triple-quoted string immediately after the shebang becomes the module's __doc__ attribute. More importantly for this tool, it also appears verbatim as the help text when you run python3 contamination_screen.py --help, because parse_args() passes __doc__ to argparse.ArgumentParser(description=__doc__). Keep this docstring accurate — it is the user-facing description of the tool.

  • ①
    argparse — command-line interface. Used only in parse_args(). Defines all the --flags the user can pass, their defaults, types, and help strings. Calling p.parse_args() returns a Namespace object — think of it as a plain object where each argument becomes an attribute, e.g. args.peak_count, args.outdir.
  • ②
    logging — timestamped terminal output. Used throughout the file via logging.info(), logging.warning(), logging.error(), logging.debug(). Configured once in main() with logging.basicConfig(). Using logging instead of print() means you get timestamps, severity levels, and the ability to suppress debug messages in production (--verbose enables debug).
  • ③
    math — used for one thing: math.isnan(). Several columns in the results dict are initialised to float("nan") when there is no value (e.g. no non-unity peak found). Before performing arithmetic on these values, the code checks math.isnan(value). Note: numpy has np.isnan() too, but math.isnan() is used for scalar floats, which is slightly faster and more explicit.
  • ④
    os — used for one thing: os.cpu_count(). The default thread count is set to min(8, os.cpu_count() or 1). os.cpu_count() returns the number of logical CPU cores, or None on some systems — the or 1 handles the None case. The cap at 8 prevents over-threading on large servers.
  • ⑤
    re — regular expressions. Used in two places: (1) in write_flagged_details() and write_plots() to sanitise sample names before using them as filenames — re.sub(r"[^A-Za-z0-9_\-]", "_", name) replaces any character that is not a letter, digit, underscore, or hyphen with an underscore. (2) In _get_plate_order() to filter out per-lane FASTQ rows from MultiQC output.
  • ⑥
    subprocess — running external programs. Used to call bcftools. Two patterns appear: subprocess.run() (via the _run() wrapper, for simple commands) and subprocess.Popen() (in filter_vcf(), for the piped 4-stage pipeline). The difference is important — see Document 3 (Key Concepts) for a full explanation.
  • ⑦
    sys — used for one thing: sys.exit(1). The code calls this whenever a fatal error occurs (e.g. VCF directory not found, bcftools fails). Exiting with code 1 tells the calling shell that the script failed. Exiting with 0 means success. This convention is important for scripting — a pipeline can check the exit code.
  • ⑧
    threading — background stderr-draining threads. Used only in filter_vcf(). When running a chain of four piped subprocesses, each process's stderr must be continuously read to prevent the OS pipe buffer from filling up and causing a deadlock. A threading.Thread is spawned for each process to drain stderr in the background. See Document 3 for a full explanation of this pattern.
  • ⑨
    ThreadPoolExecutor — parallel pairwise comparisons. The key parallelism primitive. In Phase 3, executor.map(_worker, tasks) distributes the list of pairwise comparison tasks across a pool of threads. Each thread runs _worker() independently. The results come back in the same order as the input tasks. See Document 3 for when threads help and when they don't.
  • ⑩
    combinations — generating unique pairs. combinations(sample_names, 2) yields every unique ordered pair from the list without repetition and without self-pairs. For ["A","B","C"] it gives ("A","B"), ("A","C"), ("B","C") — exactly the 3 = 3×2/2 unique pairs. This is used to build the tasks list in Phase 3.
  • ⑪
    Path from pathlib — file path objects. Every file path in the code is a Path object rather than a plain string. Path objects support clean syntax: outdir / "filtered" joins paths correctly on any OS, vcf.stem gives the filename without extension, path.exists() checks existence, path.mkdir(parents=True) creates directories. Much safer and cleaner than string concatenation with "/".
  • ⑫
    Type hints from typing. Used in function signatures like def _compare(...) -> Tuple[dict, Optional[pd.DataFrame]]. These are purely documentation — Python does not enforce them at runtime. They tell a reader (or a type checker like mypy) exactly what types a function expects and returns. Optional[X] means the value can be X or None. In Python 3.9+ you could write dict | None directly, but the typing imports keep compatibility with Python 3.8.

    numpy aliased as np. Used in _find_peaks() for the histogram: np.histogram(), np.argmax(), np.arange(), boolean array masking, and np.log2() indirectly through the ratios. Also used in write_matrix() to initialise an N×N integer matrix with np.zeros(). The as np alias is universal Python convention — you will see it in every scientific Python codebase.
  • ②
    pandas aliased as pd. Used for two main things: (1) DataFrames — tabular data with named columns, used to store variants per sample (df_cache) and to merge two samples' variant sets (pd.merge() in _compare()); (2) CSV writing — df.to_csv() writes TSV output files. The as pd alias is also universal convention.
Why no matplotlib import at the top?

matplotlib is imported inside write_plots(), not at the top of the file. This is intentional: matplotlib is optional (only needed with --plots) and is slow to import. Importing it inside the function means the tool starts up quickly even if matplotlib is not installed — it only fails at the point where a plot is actually requested.

04 Constants

contamination_screen.py Lines 37–47 
# Histogram parameters
_LOG2_RANGE = 4.0   # ①
_BIN_WIDTH  = 0.2   # ②

# Default glob for VCF files
VCF_GLOB = "*_annotated.vcf.gz"  # ③

# Default gnomAD AF threshold
_MAX_GNOMAD_AF = 0.40  # ④

# Gene symbol extracted by bcftools +split-vep as CSQ_SYMBOL  # ⑤
  • ①
    _LOG2_RANGE = 4.0 — the x-axis span of the histogram. The histogram covers log2 ratios from −4.0 to +4.0. In ratio terms, this is 2⁻⁴ to 2⁴ = 1:16 to 16:1. Any contamination fraction from ~6% (ratio ≈ 0.06, log2 ≈ −4) to ~94% is visible. In practice, contamination above 50% is very rare (and would look like a swap), so this range comfortably covers all real cases. The leading underscore signals this is a module-level private constant — it can still be overridden via the --bin-width argument.
  • ②
    _BIN_WIDTH = 0.2 — histogram resolution. Each bin spans 0.2 log2 units. A ratio of exactly 0.5 (50% contamination, log2 = −1.0) and a ratio of 0.48 (log2 = −1.06) both fall in the same bin. Narrower bins give finer resolution but need more variants per bin to show a clear peak. 0.2 was chosen empirically: it is fine enough to separate peaks at different contamination fractions, but wide enough that 10+ variants cluster into a single peak even at modest contamination levels. This is also the default for --bin-width.
  • ③
    VCF_GLOB = "*_annotated.vcf.gz" — filename pattern. This glob pattern is used to discover VCF files in the input directory. It matches filenames ending in _annotated.vcf.gz, which is the naming convention for eggd_vep output in the Uranus pipeline. If you use this tool with a different pipeline, you would override this with --vcf-glob. Note this is the only constant without a leading underscore — it is also used as the default value in the argument parser, so it needs to be publicly accessible.
  • ④
    _MAX_GNOMAD_AF = 0.40 — the gnomAD population frequency threshold. Variants with gnomAD AF ≥ 0.40 are excluded during pre-filtering. The value 0.40 was chosen empirically: at this frequency, 16% of individuals are homozygous-alt (AF² = 0.16), creating a 2:1 ratio against any heterozygous individual that exactly mimics 50% contamination. The briefing document explains this in full with empirical data. Overridable via --max-gnomad.
  • ⑤
    The final comment (no constant). This is just a note explaining that CSQ_SYMBOL (the gene name field) is produced by bcftools +split-vep in Phase 1, so it is available in the filtered VCFs loaded in Phase 2. It is documentation, not code.
Why are some constants prefixed with underscore?

_LOG2_RANGE, _BIN_WIDTH, and _MAX_GNOMAD_AF all start with _ because they are internal defaults that the rest of the module uses directly. They are not part of any public API. VCF_GLOB has no underscore because it is explicitly referenced in the argument parser as a visible default value. The distinction is a signal to readers, not enforced by Python.

07 Type hints

Every function has type hints on its parameters and return value. These are annotations — Python ignores them at runtime, but they tell you exactly what a function expects without having to read its body.

Here are the patterns you will see repeatedly:

# A function that takes a Path and returns a string
def get_sample_name(vcf: Path) -> str:

# A function that can return a DataFrame OR None
def _compare(...) -> Tuple[dict, Optional[pd.DataFrame]]:

# A function that takes a dict mapping strings to DataFrames
def _worker(args_tuple: tuple) -> dict:

# A function that takes an optional Path (can be None)
def _apply_flags(..., freemix: Optional[dict] = None, ...) -> pd.DataFrame:
  • 1
    Optional[X] means the argument can be X or None. Wherever you see Optional[dict] or Optional[pd.DataFrame], expect the code inside that function to check if x is not None: before using it.
  • 2
    Tuple[A, B] means the function returns two values as a tuple. _compare() returns Tuple[dict, Optional[pd.DataFrame]] — a results dict always, plus a shared-variants DataFrame only when include_shared_df=True.
  • 3
    Dict[str, pd.DataFrame] means a dictionary where keys are strings and values are DataFrames. This is the type of df_cache — sample name maps to its variant DataFrame.
  • 4
    -> None (explicit) or no return annotation means the function returns nothing useful — it works by side effects (writing files, modifying variables).
Reading tip

When you encounter an unfamiliar function, read its signature first: the type hints tell you what it takes and what it gives back. You can often understand what a function does just from its name + signature + docstring, without reading the body. Only read the body when you need to understand how it does it.
